# m2A Eau for Home Assistant

Unofficial Home Assistant custom integration for the **m2A / Eaupla! / Service
des Eaux (SDE)** customer portal of Mulhouse Alsace Agglomération, France.

> This project is not affiliated with, endorsed by, or supported by Mulhouse
> Alsace Agglomération. It uses the private web API used by the customer portal;
> changes to that portal may require updates to this integration.

## Features

- UI configuration through Home Assistant
- Authentication to the Eaupla!/m2A e-services portal
- Strict meter selection by physical meter number
- Hourly polling
- Manual **Refresh meter data** button
- Official meter index
- Last telemetry reading date
- Latest daily consumption
- Current-month consumption
- N / N-1 comparison
- Daily averages
- Full historical backfill, month by month
- Rolling recent-history resynchronization for late or corrected readings
- Home Assistant Recorder long-term statistics
- Compatible with the **Water** section of the Home Assistant Energy dashboard
- Manual **Resync full history** button

## Installation with HACS

This repository can be used as a HACS custom repository.

1. Install HACS if it is not already installed.
2. Open **HACS**.
3. Open the menu and choose **Custom repositories**.
4. Add:

   `https://github.com/SepuLeVrai/ha_m2a_SDE`

5. Select category **Integration**.
6. Install **m2A Eau**.
7. Restart Home Assistant.
8. Open **Settings → Devices & services → Add integration**.
9. Search for **m2A Eau**.
10. Enter:
    - your Eaupla!/m2A login;
    - your password;
    - your physical water meter number.

Example meter number used in the documentation: `ABC123456`.

## Manual installation

Copy:

`custom_components/m2a_water`

to:

`/config/custom_components/m2a_water`

Then restart Home Assistant and add **m2A Eau** from **Settings → Devices &
services**.

## Entities

The exact entity IDs are generated by Home Assistant. The integration exposes
the following entity types:

| Entity | Purpose |
|---|---|
| Official meter index | Official cumulative meter index, in m³ |
| Last telemetry reading | Date of the most recent supplier reading |
| Last daily consumption | Most recent daily consumption, in litres |
| Current month consumption | Sum of available daily readings for the month |
| Same period N-1 | Consumption for the comparable previous-year period |
| Evolution N / N-1 | Percentage change |
| Daily average | Current-period average, in litres/day |
| Daily average N-1 | Previous-year comparable average |
| Historical days imported | Diagnostic count and import range |
| Refresh meter data | Requests the same forced refresh used by the web portal |
| Resync full history | Starts a complete historical backfill |

## Energy dashboard / Water

For historical water consumption, use the external long-term statistic created
by the integration:

`m2a_water:<meter_number>_daily_consumption`

This is preferable to using the raw meter-index sensor for the Energy dashboard,
because the statistic contains the supplier's daily historical readings and can
be backfilled.

The raw meter index remains useful as the current official cumulative value.

## Historical import

The first complete backfill is downloaded **from newest to oldest**, one month at
a time. Progress is saved locally after every successful month.

Old periods that are unavailable from the supplier do not abort the whole
import. The integration also reads the portal's N-1 comparison data and maps it
back to its real previous-year dates when it is useful for historical coverage.

Recent history is re-read periodically so delayed or corrected supplier readings
can be imported later.

Home Assistant may need some additional time after a large backfill to process
and aggregate Recorder statistics before every month becomes visible in the
Energy dashboard.

## Privacy and security

The customer portal has been observed returning subscription records beyond the
selected meter. This integration is deliberately defensive:

- only the installation whose `counter_number` exactly matches the configured
  meter number is retained;
- unrelated subscriptions are not exposed as Home Assistant entities;
- raw subscription responses are not logged;
- JWTs are held in memory and are not written to the integration configuration;
- the integration automatically re-authenticates when required.

Your username and password are stored in the Home Assistant Config Entry, like
many cloud integrations. Protect your Home Assistant instance and backups.

**Never publish passwords, JWTs, cookies, session identifiers, full authenticated
API responses, addresses, subscriber names or meter numbers belonging to other
people in a GitHub issue.**

## Update frequency

The integration polls hourly and can request a forced supplier refresh. A forced
refresh asks the m2A information system to update its data; it does **not**
guarantee an immediate radio read from the physical meter.

## Troubleshooting

Enable debug logging temporarily if needed:

```yaml
logger:
  logs:
    custom_components.m2a_water: debug
```

Restart Home Assistant, reproduce the problem, then inspect the logs. Remove or
disable debug logging afterwards.

When reporting an issue, redact all authentication data and personal
information.
